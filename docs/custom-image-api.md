# 自定义供应商的 OpenAI Images 接口

Cindy Gateway 已有的图片、视频目录继续跟随网关。自定义连接可单独启用
OpenAI Images 接口，让使用 Core 媒体能力的 Art 等插件调用自己的图片来源。
适配按接口契约复用，不按中转产品名分支。

## 使用方式

1. 在供应商的连接设置中选中持有该图片来源的 Agent 连接，填写 API 地址与 API Key。
   本机回环地址也可以使用无鉴权连接。
2. 勾选「使用 OpenAI Images 接口」。只有实际提供下列两个端点的连接才应开启。
   仅兼容对话接口，或订阅中能在网页上作图，不能证明该连接有 Images API。
3. 获取模型列表，并在常规模型设置中确认目标模型属于图片生成类型。
   返回列表未标识类型时，手动调整模型能力；不会按供应商名称自动开启。
4. 在 Art 的图片生成、图片编辑能力中选用该来源的模型。

连接地址可以填写 API origin、以 `/v1` 结尾的地址或带路径前缀的 `/v1` 地址。
例如 `http://127.0.0.1:8317/v1` 对应
`http://127.0.0.1:8317/v1/images/generations`。
未以 `/v1` 结尾的地址会追加 `/v1`，路径前缀保留。

## 一期支持的契约

| 操作 | 接口 | 请求与响应 |
| --- | --- | --- |
| 图片生成 | `POST /images/generations` | JSON；原样发送模型 ID、prompt，使用既有 OpenAI 图片参数规范化 |
| 图片编辑 | `POST /images/edits` | multipart；参考图与 model、prompt、size、quality |
| 返回图片 | `data[0].b64_json` 或 `data[0].url` | 客户端下载、校验并保存为受管媒体 |

鉴权为该 Agent 连接的 API Key（Bearer），或仅本机回环地址的无鉴权模式。
不会借用其他 Agent、其他供应商或订阅登录的凭证。自定义业务请求头保留，
鉴权、账号、协议会话和 multipart 的请求头由客户端隔离或生成。
模型级地址覆盖必须与连接地址同源；付费提交不跟随重定向。

CPA/CLIProxyAPI、Sub2API 等自建中转只要提供上述契约即可复用此通道；
它们内部如何管理订阅或 CLI，不进入 Cindy 的媒体适配层。
是否能使用某个模型仍取决于中转实际开放的接口、模型及账号权限。

## 已安装用户与失败恢复

- 新字段 `imageApi: "openai-images"` 为可选配置。缺省不启用，不自动改变已存连接或付费来源。
- Gateway、OpenAI、Codex 和 xAI 既有通道优先保留；不替换原有原生订阅通道。
- 本次不修改插件包、批准记录、权限指纹或凭证存储布局，无需重新安装或重新授权插件。
- URL 结果先保存调用记录，再走既有下载许可与安全校验。下载不携带生成来源的 API Key。
  下载失败后使用原 invocation 再次执行 request，只恢复同一结果，不重新付费生成。
- 上游提交结果不确定时不自动重提，不自动换模型或换来源；拒绝与诊断文本脱敏后返回。
- 新来源使用 Core 媒体能力；冻结的旧 `cindy-request` 同步接口不扩展自定义来源。
  旧插件已有能力保持原状。要使用新来源，插件需要采用 Core 媒体能力。

## 后续边界

本阶段不实现视频接口、原生 Gemini/其他私有图片协议、任意 CLI 进程驱动、
网页 Cookie 或私有订阅登录的复用，也不新增逐家 OAuth 适配。
只开放生成、缺少编辑端点的来源暂不应开启此选项。
新协议应独立评估其主流程度和稳定契约，避免在 OpenAI Images 通道上叠加供应商特例。
