# 桌面伙伴语音模式

## 范围与行为

- 入口位于本机伙伴的一对一对话标题栏。沿用伙伴 canonical 任务、模型、上下文、工作目录和工具权限，不创建第二条任务或切换聊天模型。
- 用户明确点击开始后采集麦克风。使用现有语音输入的 ASR 设置和当前账号的服务模式；不启用听写润色，不修改原有听写行为。
- 停顿约 900ms 后等待 ASR 的最终文字，再用短暂的稳定窗口合并同一段发言。只有最终、非空文字能自动发送；声音活动检测本身不能产生消息。
- 原任务空闲时正常发送，仍在运行时沿既有插话路径投递。语音是本机用户本人输入，不盖自动化或远程设备来源标签，不增加系统提示词。识别结果按普通文字发送，不执行桌面斜杠命令。
- 最终回复经过持久化完成标记确认后才朗读。按本次语音发送的 clientId 关联，不朗读历史、过程文字、工具、子代理、内部协调或群来源私信。文本消息始终是对话记录的正本。
- 独立选择朗读模型和音色，按当前账号下的伙伴保存，不改变聊天模型。来源包括有权限的 Cindy AI，以及已连接的本地 BYOK 供应商；候选必须是 `audio_speech`、未停用且具备可用的 API key 或明确的本机免鉴权连接。同名模型按连接 ID、runtime 和上游模型 ID 区分，不能借另一连接的密钥。无候选时显示空状态，不采集麦克风。
- BYOK 支持 OpenAI 兼容、ElevenLabs、MiniMax 三种语音接口。已声明的 OpenAI speech 协议或已知官方端点可确定默认接口；其余候选（包括显式未验证协议）必须由用户在语音面板明确选择接口，不能只凭模型名、`mode` 或聊天协议推断。这个覆盖仅作用于当前伙伴的朗读，不重写公共 Registry 或供应商的聊天协议。ElevenLabs / MiniMax 需填写账号可用的音色 ID；本次不做音色目录、试听或克隆。
- 模型、语音接口和音色为伙伴级显式偏好，打开面板、重启后保留。恢复默认删除该伙伴的选择，继续跟随可用目录；已有旧版全局偏好仍可继承，单独重置一个伙伴时以 `null` 清除该伙伴的旧偏好继承，不复制默认模型、不影响其他伙伴。保存失败明确提示。保存的连接消失或停用时保留选择并禁止开始，不静默改用同名模型。
- 刷新重新读取当前有效目录，并尝试刷新 Cindy AI；Gateway 刷新失败不阻止本机 BYOK 目录显示。新增第三方型号仍沿设置页已有的获取列表、手动添加和启用流程。
- 朗读结束继续监听。用户开口时立即取消待生成及正在播放的声音；新的文字仍投递到原任务。停止朗读不会取消 Agent 工具、清空任务队列或代答权限确认。
- 需要确认权限、问题或计划，或任务队列暂停时，关闭麦克风并暂停语音模式；用户完成确认后显式继续。静音、锁屏、休眠、切走任务、关面板、账号切换同样释放采集和播放资源，不在后台重新开始。
- 未发送的文字在可恢复错误或暂停后留在面板内；用户可选中复制或明确重新连接并发送。TTS 失败保留任务中的文字回复，不自动重发用户消息。

## 交互与动效

面板保留伙伴头像和姓名，持续显示连接、监听、思考、准备语音、朗读或暂停状态。音量条反映实际输入或输出音量，没有循环伪造的声波。进入动效和音量条只变换 opacity/transform，使用现有 motion token，并支持减少动态效果。模型、接口和音色可在开始前或暂停后更换，静止配置区采用紧凑的头像与状态行；语音运行时恢复集中呈现的伙伴头像和音量条。进行中的结束、静音及面板关闭按钮不随内容滚走，暂停后可继续或关闭。面板最多占视口高度的 65%，中间内容独立滚动。Light/Dark 使用语义颜色。

设计依据为 `DESIGN.md` §4 标准控件、§5 圆角分层、§14.4 动效与 `design-governance.md` §13 点击层分类：标题栏语音入口是 32px 的普通动作按钮，沿用同栏的 pill；面板和未发送文字框属于容器，使用 12px 圆角；音量条是无交互的指示层，不是按钮。设置、开始、静音、结束等操作复用现有 Button / Select / Input / FormField，模型、接口和音色均有可见标签。较窄的窗口将接口和音色折行，操作区保持可见。

## 执行边界

- 当前仅支持 Desktop、本机伙伴一对一。群聊、Mobile、远程控制的麦克风、原生 Realtime speech-to-speech 不在此实现内。
- 新 IPC 只接受可信应用顶层 Renderer，按窗口、账号代次、callId 和 canonical 任务绑定。callId 在发起请求前生成，使结束按钮也能取消连接过程；它不是授权凭证。接口不加入 device-link 或插件白名单。模型权限在开始和每次 TTS 请求、读取时复核。
- ASR 适配器额外提供按上游 utterance/item ID 标识的分段事件，现有累积 `AsrEvent` 合同保持不变。连接在 150 秒轮换，沿用 voice-server 的 dictation 协议；切换期间最多缓存 5 秒输入，不能无声丢弃或重复发送前文。
- Gateway 执行合同为 OpenAI 兼容 `POST <下发的 baseUrl>/audio/speech`，body 包含 `model`、`voice`、`input`、`response_format: pcm`。PCM 固定为该协议规定的 24kHz、单声道、16bit little-endian。显式声明其他 native API 或 `null` 未验证 API 的 Cindy AI 模型不进入选择器；未声明协议的 Gateway 新模型沿用此端点合同。下发 `mode` 只代表能力分类，不证明具体音色、音频格式或端点可用。
- 凭证只在 Main：Gateway 使用当前账号配对的 baseUrl / 密钥，BYOK 复用对应连接、对应 runtime 的 safeStorage 密钥和固定请求头。排除原生订阅 OAuth、远程或共享供应商；per-model 地址不得跨越凭证所属连接的 origin。开始时固定连接，每次合成与音频读取复核资格及路由/密钥是否变化；变化则停止该语音请求。禁止自动切换到其他供应商、系统朗读或另一条凭证。响应按 Renderer 播放速度读取，播放只预排约 300ms；中断丢弃旧请求和迟到音频。原始音频只在内存，不新增录音文件或对话音频归档。
- 初始实现的声音活动判断是带迟滞的音量检测，配合浏览器回声消除与降噪。它不是语义 VAD，不能保证所有扬声器、蓝牙或噪声环境都能准确分辨插话。

## BYOK 音频合同

| 接口 | 请求与鉴权 | 响应 |
| --- | --- | --- |
| OpenAI 兼容 | `<base>/audio/speech`，Bearer，`model / voice / input / response_format: pcm` | 原始 24kHz、单声道、16bit little-endian PCM |
| ElevenLabs | `<base>/text-to-speech/<voiceId>/stream?output_format=pcm_24000`，`xi-api-key`，`model_id / text` | 原始 PCM |
| MiniMax | `<base>/t2a_v2`，Bearer，`stream: true`、`exclude_aggregated_audio: true`、`output_format: hex`、`voice_setting.voice_id`、24kHz 单声道 PCM | SSE JSON 的 hex 音频；检查业务错误及格式，结束包的聚合音频不重复播放 |

官方域名使用文档规定的 `/v1` 语音端点，MiniMax 的 `/anthropic` 聊天路径不会被沿用。用户指定的兼容代理保留配置的 API base 路径前缀；如果代理提供不同的语音根路径，应在设置中新增独立连接。接口选择不证明供应商的型号、付费方案或音色可用，执行失败仍回到文字。

原生接口依据：[ElevenLabs stream](https://elevenlabs.io/docs/api-reference/text-to-speech/stream)、[MiniMax HTTP TTS](https://platform.minimax.io/docs/api-reference/speech-t2a-http)。响应有类型、大小、超时和完整性检查，重定向被拒绝，上游原始错误不穿过 IPC。流式传输与插话取消共用原有代次检查和播放背压，不增加音频落盘。

## 后续扩展计划

以下为后续演进方向，本 PR 尚未实现适配器拆分、统一参数描述或公共 Registry schema 扩展，也不包含 Qwen / CosyVoice 原生执行器。

- **独立协议适配器**：接入更多原生协议时，先将现有 OpenAI 兼容、ElevenLabs、MiniMax 分支及响应解码整理为独立的 TypeScript 适配器。适配器负责各协议的请求序列化、传输及响应解析；公共层统一音频格式、完成、错误与取消合同，继续复用账号/任务绑定、读取背压、资源上限和迟到音频丢弃，不增加第二套伙伴任务或播放状态机。Qwen / CosyVoice 按所接具体 API 的 HTTP、SSE 或 WebSocket 合同实现，不能只替换 URL。
- **统一参数定义与校验**：用共享的类型化参数描述约定必填项、默认值、枚举、范围和错误语义，让 Renderer 表单与 Main 校验复用同一规则；Main 在执行前再次校验。音色及后续语速、语言等参数按实际协议和型号能力开放，各厂商字段映射仍由适配器负责。当前固定输出格式和参数限制需在迁移时保留，新增能力以适配器实际实现及验证为准。
- **公共 Registry 扩展**：后续可补充已验证的原生协议标识、型号支持的参数与限制、资料来源。声明须对应实际供应商/型号路由：同一型号通过原厂端点与兼容 Gateway 接入时，协议可以不同；不能从品牌、型号名称或 `audio_speech` 推断。Registry 负责描述能力，协议执行继续保留在代码中，不引入远端 JSON 请求模板或脚本执行机制。
- **正本与兼容性**：新增公共字段或协议枚举时，协调更新 cindy-server 正本、客户端 Bean/解析与校验、客户端离线副本及相应契约测试；按既有 schema/能力协商兼容旧客户端。保留未声明与显式 `null` 的区别及用户显式覆盖语义，未知协议不能因此成为已支持协议。分别记录客户端支持、服务端实现与生产部署状态；目录资料不新增用户可访问的模型、授权或执行路由。
- **配置存储延续**：API base 和密钥继续复用已有供应商连接与凭证存储，伙伴模型、音色等偏好继续使用现有账号隔离的本地设置，不额外创建通用协议配置文件。若后续把接口覆盖从伙伴偏好调整为连接/型号路由配置，须兼容并保留已有显式选择，不能静默覆盖或丢失设置。
- **扩展验收**：每个新适配器需覆盖参数错误、流式完成、业务错误、取消与迟到数据，再用真实供应商验证型号、音色和连续语音体验。新增 Registry 条目或测试替身通过均不能替代真实执行验收。

## 验证

自动化覆盖分段去重、乱序完成、空转写、连接轮换、权限与账号边界、取消启动、插话抢占、迟到音频、PCM 字节边界、回复关联、无模型空状态及现有 ASR 回归。BYOK 回归覆盖接口请求、SSE 断帧与结束聚合包、连接/密钥隔离、停用与账号切换、伙伴偏好重开与重置、未知接口须用户选择，以及合成失败不换供应商、不重发消息。

没有真实 Gateway / BYOK TTS 账号可用于验收时，自动化和组件预览使用明确的测试替身；产品目录不添加演示模型。真实模型开放后，还需验证其音色和 PCM 合同，并在 macOS/Windows 的耳机、扬声器、蓝牙设备上验证连续多轮、回声与插话延迟。测试替身不构成这些项目已通过的证据。
